# Protocolo de Prueba de Usuario — Laboratorio 8

Este documento es la plantilla para conducir la prueba de usuario que pide
la Parte 1 de la guía. Complétala mientras observas a tu usuario de
prueba; no se la leas en voz alta ni le expliques cómo se usa el proyecto
antes de empezar.

## 1. Antes de la prueba

- **Usuario de prueba:** alguien que NO haya visto el proyecto antes
  (compañero, familiar, amigo). No debe ser alguien del curso que ya
  conozca la arquitectura.
- **Qué prepara**: el proyecto corriendo en el editor (F5) o la build Web
  publicada, ya cargado, listo para que la otra persona tome el control.
- **Qué le dices antes de empezar** (guion sugerido, breve y neutral):
  > "Te voy a mostrar un configurador de motos. Quiero que explores
  > libremente como si fuera la primera vez que lo ves, y que digas en voz
  > alta lo que estás pensando o intentando hacer en cada momento. No hay
  > respuestas correctas o incorrectas, lo que busco es ver en qué partes
  > te confundes."
- **Lo que NO debes hacer**: no le digas qué botón presionar, no corrijas
  en el momento, no le expliques qué hace algo si se queda trabado —
  anota que se quedó trabado y sigue observando.

## 2. Tareas que debe intentar (sin ayuda)

1. Llegar al menú principal y entender qué opciones hay.
2. Entrar al minijuego "Conseguir Cupones" y jugarlo sin indicaciones.
3. Entrar al configurador y elegir un color + al menos un accesorio.
4. Llegar a la factura y confirmar la compra.
5. Volver al menú principal.

## 3. Qué observar y anotar (formato)

Por cada interacción relevante, registra:

| Momento / pantalla | ¿Qué intentó hacer? | ¿Lo logró a la primera? | ¿Dudó, preguntó algo, o dijo algo en voz alta? |
|---|---|---|---|
| Ej: Minijuego, inicio | Buscar cómo moverse | No — probó flechas y luego A/D | "¿Con qué me muevo?" |
| | | | |
| | | | |
| | | | |

Preguntas de seguimiento para hacer **después** de que termine (no durante):

- ¿Hubo algún momento en el que no supieras qué hacer? ¿Cuál?
- ¿Hubo algo en lo que esperabas que pasara algo distinto a lo que pasó?
- Del 1 al 5, ¿qué tan claro te pareció el proceso completo?
- ¿Qué cambiarías primero si pudieras pedir una mejora?

## 4. Después de la prueba

Pasa las anotaciones de la tabla a `doc/ux/hallazgos_ux_lab8.md`, eligiendo
las 2-3 fricciones más claras y describiéndolas en formato
Situación / Mejora propuesta / Resultado esperado.
